# Acceso privado por cohortes — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que solo los miembros de una cohorte (y admins) accedan al contenido de un curso privado, empezando por «Modelización Dinámica de Carbono» (`69d50406663e8648d7ee1f08`).

**Architecture:** Una función pura `resolveAccess` decide el nivel (`full|readonly|denied`); un servicio la alimenta con las cohortes del curso y un middleware `requireCourseAccess(action, courseIdFrom)` la aplica en todas las rutas de contenido. Los cursos públicos devuelven `full/public` y siguen por su lógica actual. Altas por email (pendiente → activo al entrar con ese email) y por enlace de invitación con token hasheado.

**Tech Stack:** Express 5, Mongoose 9, `node:test` (backend, stubs de modelos), React + Vite (front), Cloudinary.

**Spec:** `docs/superpowers/specs/2026-10-22-cohortes-design.md` (+ la tarea original)

## Global Constraints

- `accessMode` por defecto `'public'`; la migración no cambia el comportamiento de ningún curso existente.
- Token de invitación: `crypto.randomBytes(32).toString('base64url')`; en BD solo `sha256` hex.
- Email normalizado = `String(email).trim().toLowerCase()` en todos los sitios (un único helper).
- Seguridad solo en el servidor; el front solo refleja `access`.
- Nunca escribir en la BD de producción desde local (el `.env` del front apunta a PROD). Scripts con `--dry-run` por defecto.
- Respuestas personalizadas por acceso: `Cache-Control: private, no-store` + `Vary: Authorization`.
- Copy: «Curso privado – acceso por invitación», «Avísame de la próxima edición», «Plaza reservada».
- Estilo de UI: componentes de `components/admin/ui` y de la ficha (`components/courses/sheet`) existentes.

## Rutas protegidas (inventario completo)

| Ruta | Hoy | Después |
|---|---|---|
| `GET /api/courses` | pública, devuelve materiales con URL | privados: se quitan `archivo/archivoEn` de materiales y actividades |
| `GET /api/courses/:id` | pública, todo | `optionalAuth`; privado sin acceso → ficha redactada + `access` |
| `GET /api/courses/:id/video` | full si inscrito + `isOpen` | además `read` |
| `GET /api/courses/:id/materiales/:materialId` | — (nueva) | `read` → redirige a URL firmada de vida corta |
| `GET /api/pdf-proxy?url=` | proxy abierto | host exacto; si es material de curso privado, `read` |
| `GET /api/ejercicios/curso/:cursoId`, `GET /api/ejercicios/:ejercicioId` | públicas | `read` (curso del ejercicio) |
| `POST/PUT/DELETE /api/ejercicios` | **sin auth** | `autenticar, soloAdmin` |
| `GET /api/tests/:cursoId/temas/:temaId/test`, `POST …/validar` | públicas | `read` |
| `POST /api/tests/test` | **sin auth** | `autenticar, soloAdmin` |
| `GET /api/entregas/ejercicio/:id/usuario`, `GET /api/entregas/curso/:cursoId/usuario` | JWT | + `read` |
| `POST /api/entregas/ejercicio/:id` | JWT, `cursoId` del body | + `write`; curso derivado del ejercicio |
| `DELETE /api/entregas/:entregaId` | JWT | + `write` (curso de la entrega) |
| `POST /api/users/enroll/:courseId` | JWT | + `write` |
| `PUT /api/users/enrollment/:courseId/{language,progress,complete}`, `POST …/test/:temaId/complete` | JWT | + `read` |
| `GET /api/users/enrollments` | JWT, popula curso entero | cursos sin acceso → redactados |
| `GET /api/users/enrollment/:courseId`, `/api/terms/*` | JWT | sin cambio (no sirven contenido) |
| Admin (`/api/courses` CRUD, `/api/entregas/admin/*`, `/api/users/admin/*`) | `soloAdmin` | sin cambio |
| `express.static('public')` | solo `upload-*.html` de admin y carpeta vacía | sin cambio |

## Review Focus

1. Cambio de email/usuario: el canje por enlace añade al **usuario logueado** aunque su email no coincida; la vinculación por email solo actúa sobre miembros `pending` con `user: null` → test en Task 6 («no roba una plaza ya vinculada a otro usuario»).
2. Dos canjes simultáneos del último uso: el incremento de `uses` es condicional (`uses < maxUses`) en un único `findOneAndUpdate` → test en Task 7 con dos `redeem` en paralelo.
3. Mayúsculas/espacios en emails pegados en el admin y al registrarse → test en Task 6 y Task 8 con `'  Ana@X.es '`.
4. Fechas límite exactas: `now === startsAt` es full, `now === endsAt` ya es fin → tests en Task 2.
5. ID de curso inválido o inexistente en rutas protegidas → 404, nunca 500 ni fuga → test en Task 3.
